# Phase 2: `agentview` standalone CLI

Goal: a program run in a second terminal (`agentview`) that watches every Claude Code session on the machine
from its transcript files, lists them (spec screens 5 / 5b), and opens one session as the full-screen dialog
(spec screen 6) with the agent detail (spec screen 2). Same core reducer and view as the plugin.

Read first: `CLAUDE.md` (code standards, binding), `docs/design/tui-spec.txt` (screens 5, 5b, 6, key table),
`docs/design/spec-generator.js` (`sessions()` is the reference for the session list).

## Rules for every task

- TDD: failing test first. `npm test` and `npm run typecheck` must pass; `claude plugin test .` must still pass.
- Layers: `src/cli/` is the only new layer allowed to use Node APIs (`fs`, `path`, `os`, `process`). Pure logic
  in `src/cli/` (parsers, list building, painting, screen diffing) takes no Node APIs and gets time as an argument,
  so it stays testable. `src/view/` stays pure. `src/core/` is unchanged unless a task says so.
- Accuracy rule of the maintainer: exact data or `—`. Never estimate. The transcript does not say how a session is
  billed, so the CLI never shows cost: pass `billing: { kind: 'unknown' }` to renderers (cost slot shows `—`, no
  COST column, no `▲`).
- Low resource rule: no work when nothing changes. Poll with `fs.stat` at most once per second, read only the bytes
  appended since the last read, redraw at most once per second (plus once per key press), and write only the
  terminal lines that changed. A test must prove "nothing changed ⇒ zero bytes written".
- Commit after each task, Conventional Commits, ending with the `Co-Authored-By:` line of the model that wrote it.

## Transcript format (verified on Claude Code 2.1.302)

- Main transcript: `~/.claude/projects/<project-dir>/<sessionId>.jsonl`, one JSON object per line.
- Subagents: `~/.claude/projects/<project-dir>/<sessionId>/subagents/agent-<agentId>.jsonl` plus
  `agent-<agentId>.meta.json` = `{ agentType, description, parentAgentId?, toolUseId, model?, spawnDepth, finished? }`.
  No `parentAgentId` means the parent is `main`.
- Every record: `type`, `timestamp` (ISO string), `sessionId`, `cwd`; subagent records also carry `agentId`.
- `type: 'assistant'`: `message.id`, `message.model`, `message.usage` = `{ input_tokens, output_tokens,
  cache_read_input_tokens, cache_creation_input_tokens }`, `message.content[]` with `{ type: 'tool_use', id, name,
  input }`. One API response is split over several records with the same `message.id` and the same `usage`:
  count usage once per `message.id`.
- `type: 'user'`: `message.content` is a string for a real user prompt (main turn starts; skip records with
  `isMeta: true`), or a list holding `{ type: 'tool_result', tool_use_id, is_error? }` blocks (tool ends).
  `toolUseResult` of an Agent call: `{ status: 'async_launched' | 'completed', agentId }`; `completed` ends that agent.
- `type: 'system'`, `subtype: 'turn_duration'`: main turn ended.
- `type: 'queue-operation'`, `operation: 'enqueue'`, `content` containing `<task-notification>` with
  `<task-id>ID</task-id>` and `<status>completed|failed|killed</status>`: background agent ID ended
  (`ok` only for `completed`).
- `TodoWrite` tool_use `input.todos` → `todos` event; `TaskCreate` / `TaskUpdate` → see `src/mod/adapter.ts`
  `taskEvents` (reuse the same shapes; the TaskCreate id is in the tool result's `toolUseResult.task.id`).
- Ignore every other record type. Unknown shapes are skipped, never thrown on.

## Tasks

### 2.2 Transcript adapter — `src/cli/transcript.ts` (pure)

- `type ParseState = { readonly seenMessageIds: ReadonlySet<string>; readonly toolNames: Readonly<Record<string,string>> }`
  and `initialParseState()`.
- `parseRecord(state, record: unknown, agentId: string): { state: ParseState; events: AgentEvent[] }` — `agentId`
  is `'main'` for the main file, else the subagent id. Map as in "Transcript format": `tool.start`, `tool.end`,
  `usage` (once per message id, model from the record), `turn` start/end (main only), `agent.end` (Agent result
  `completed`, task-notification), `todos`, `task.add` / `task.set`, and a `heartbeat` for the agent on every
  assistant record. `at` = `Date.parse(record.timestamp)`; a record without a valid timestamp yields no events.
- `metaStart(meta: unknown, agentId: string, at: number): AgentEvent | null` → `agent.start` with
  `parentId = parentAgentId ?? 'main'`, `type = agentType`, `description`, `model`.
- `parseLines(state, text, agentId)`: splits on `\n`, skips blank and invalid JSON lines.
- Tests `tests/cli/transcript.spec.ts` on small anonymized fixtures in `tests/fixtures/transcripts/` (hand-made
  from the format above; no real prompts or paths). One behavior per test, including: usage counted once for a
  split message; tool_result with `is_error` gives `ok: false`; invalid JSON line skipped; task-notification
  `failed` gives `ok: false`.

### 2.3 Session list view — `src/view/sessions.ts` (pure)

- Port of `sessions()` in `docs/design/spec-generator.js`, readable names, byte-identical output. Input:
  `SessionListItem = { status: RowStatus; project: string; id: string; agents: string; tok: number; cost: number;
  plan: string; act: string; ago: string }` and `SessionListOpts = { W, active: SessionListItem[], recent:
  SessionListItem[], selId?: string, totalTok, totalCost, hasCost: boolean, spin?: string, ascii?: boolean,
  minRows?: number, win?: [number, number] }`.
- `hasCost: false` drops the COST column and shows `—` in place of the header cost total.
- Golden tests: screens `5` (120 cols) and `5b` (80 cols) from `src/view/spec-golden.ts` match exactly with the
  spec's data and `hasCost: true`. Extra tests: `hasCost: false`; empty lists show one dim line
  `no Claude Code sessions found in ~/.claude/projects`; more sessions than rows scroll like the dialog (`windowFor`).

### 2.4 Painting and screen diff — `src/cli/ansi.ts`, `src/cli/screen.ts` (pure)

- `toAnsi(line)`: `{codes|text}` → SGR escapes using `runs()` from `src/mod/paint.ts` (move `runs` and
  `COLOR_OF_CODE` to `src/view/runs.ts` if `src/cli` must not import `src/mod`; keep `src/mod/paint.ts` re-exporting).
  Codes: `d` dim, `B` bold, `I` inverse, `c y g r b` colors 36 33 32 31 34. Each run ends with `\x1b[0m`.
- `diffScreen(previous: string[], next: string[], rows: number): string` → escape string that rewrites only lines
  that differ (`\x1b[<row>;1H` + line + `\x1b[K`), clears lines past the end, returns `''` when equal.
- Tests: equal screens give `''`; one changed line writes only that row; shrinking clears the rest.

### 2.5 Session list model — `src/cli/session-list.ts` (pure)

- `summarizeSession(state: SessionState, info: { project: string; lastAt: number }, now: number): SessionListItem`:
  status = `running` if any agent runs, else `waiting` if any waits, else `unknown` if main is unknown, else
  `failed` if any failed, else `done`. agents = count plus `(N run)` / `(N wait)` like the spec. plan = main plan
  percent or `—`. act = latest action summary of the newest active agent; `session finished` when done; `no
  heartbeat` when unknown. ago = `fmtT` of `now - lastAt` in the spec's units (`2s`, `1m35s`, `38m`, `2h`, `1d`).
- `groupSessions(items)`: ACTIVE = running/waiting, RECENT = the rest; each sorted by session start, newest first,
  stable. Project path: home directory shown as `~` (the home path is an argument).

### 2.6 Watcher — `src/cli/watcher.ts` (Node)

- Finds `~/.claude/projects/*/*.jsonl` (override with `AGENTVIEW_PROJECTS_DIR` for tests), only files modified in
  the last 7 days, newest 50 at most. Per file keeps byte offset + `ParseState` + `SessionState`; on each poll:
  `fs.stat`, read only new bytes (keep a partial last line for the next read), reduce the events.
- Subagents: on each poll of a session whose main file changed (or whose subagent dir mtime changed) list
  `subagents/`, read new `.meta.json` once (emit `metaStart` at the first record time of its `.jsonl`, or the meta
  file mtime), tail each `agent-*.jsonl` the same way with its `agentId`. `finished: true` in meta with no end
  event yet → `agent.end ok` at the last record time.
- `poll(now)` returns whether anything changed. No timers inside; the app owns the 1 s interval.
- Tests in `tests/cli/watcher.spec.ts` use a temp dir (Node `fs.mkdtemp`): append lines, poll, check state; a poll
  with no file change reads zero bytes (spy on the read function passed in) and returns `false`.

### 2.7 App and keys — `src/cli/app.ts`, `src/cli/main.ts`, `bin/agentview.js`

- Screens: list (spec 5), session (spec 6: `renderDialog` with `path`, `sid`, hints `↑↓ select · ⏎ details ·
  esc sessions · q quit`, `minRows` = terminal rows, `billing: { kind: 'unknown' }`), detail (spec 2:
  `renderDetail`, hints `↑↓ prev / next agent · esc back to tree · q quit`). Keys exactly per the table in
  `AGENTVIEW.md` §3.5. Selection follows ids, not indexes.
- The pure part (`app.ts`): `type AppState`, `handleKey(state, key) → state | 'quit'`, `renderApp(state, sessions,
  now, columns, rows) → string[]`. The Node part (`main.ts`): alt screen `\x1b[?1049h`, hide cursor, raw stdin,
  `SIGWINCH` → full redraw, 1 s `setInterval` that polls the watcher and redraws only if something changed or the
  clock text changed and an agent is running; restore the terminal on `q`, `SIGINT`, `SIGTERM` and uncaught errors.
- ASCII fallback when `AGENTVIEW_ASCII=1` or the locale is not UTF-8.
- `bin/agentview.js`: `#!/usr/bin/env node`, imports `../dist/cli/main.js`.
- Build: `scripts/build-cli.mjs` (no dependencies) runs `tsc -p tsconfig.cli.json` (emit to `dist/`, only `src/`) and
  rewrites relative import specifiers in `dist/**/*.js` to end in `.js`. `package.json`: `bin`, `build` script,
  `prepare: npm run build`, `files`. `dist/` in `.gitignore`.
- Tests: `tests/cli/app.spec.ts` for keys and screen switching (pure). Manual: run in a pty against the real
  `~/.claude/projects` and compare with the dialog.
